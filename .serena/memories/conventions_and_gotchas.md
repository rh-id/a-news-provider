# Conventions & Gotchas

## Language & Build Conventions
- **Pure Java** — never introduce Kotlin. All modules use Java 17 toolchain with core library desugaring (`desugar_jdk_libs:2.1.5`).
- **Room compiler via `annotationProcessor`** — this project has NO kapt and NO ksp. Keep it that way when adding annotation processors.
- **Gradle version catalog** — dependency versions live in `gradle/libs.versions.toml`; build files use `libs.*` aliases. Add/change versions there, never inline coordinates.
- RxJava is pinned to **3.1.12** because it is the final 3.x release (RxJava 4 is alpha-only, not on Maven Central) and 3.x keeps minSdk 21 — do not upgrade casually.
- minSdk 21: avoid APIs above that or guard with SDK checks (see `RssDateParser` SDK-aware format lists; `NotificationPermissionPolicy` guards POST_NOTIFICATIONS on 13+).
- Gradle Groovy DSL (not Kotlin DSL); AGP 9.4.1; deps resolved from google/mavenCentral/jitpack (`com.github.rh-id:*` for the author's libs).

## Architectural Conventions
- New screens = new `StatefulView` page + route constant in `Routes` + factory entry in `AppProviderModule.getNavigator()`. No Fragments, no second Activity.
- New business logic = new Command class in `app/.../provider/command/` + lazy registration in `CommandProviderModule`. UI never touches DAOs/workers directly — always via `RssRepository`, commands, or the non-UI `RssService` (add-feed core).
- New dependencies go into the matching ProviderModule (`BaseProviderModule` for infra, `DatabaseProviderModule` for DB, `NetworkProviderModule` for HTTP, `CommandProviderModule` for commands). Register async (`registerAsync`) or lazy (`registerLazy`) where construction is expensive.
- Per-page state/subscriptions must be disposed via the page's scoped `StatefulViewProvider` / `RxDisposer` — never leak subscriptions past page pop. Exception: deliberately shared state like the app-scoped `PagedRssItemsCmd` used by both list and detail pages.
- Background jobs = WorkManager workers with unique names registered in `ConstantsWork`; input data keys in `ConstantsKey`. Sync work uses `NetworkType.CONNECTED` constraint and `ExistingWorkPolicy.KEEP`.
- License list for the Licenses screen is GENERATED (`gradle/license-html-generator.gradle`, overrides in `app/licenses.yml`) — never hand-edit `app/src/main/assets/licenses.html` or reintroduce cookpad license-tools.

## Localization Conventions (added with Chinese, commit 6f44c33)
- Translated strings files must have the EXACT same `<string name>` keys as `values/strings.xml` (same count/order) and preserve every `%s`/`%d`/`%n$s` placeholder — build breaks or crashes otherwise.
- `app_name` stays "News Provider" untranslated in locale files (matches 9/10 existing locales; only Indonesian translates it).
- Full-width Chinese quotes “” need no XML escaping (unlike English `\"Error: %s\"`).
- No `<resourceConfigurations>` filter and no `localeConfig.xml` exist — new `values-<locale>` dirs are picked up automatically, no Gradle/manifest changes needed.
- Adding a locale = strings in `app` + `component-network` + fastlane dir; store dir naming may differ from resource dir (`values-zh` vs `zh-CN`, see `mem:fastlane_and_release`).

## Testing Conventions
- Shared test doubles used by BOTH unit and instrumented tests go in `app/src/sharedTest/java` (auto-added to both source sets).
- Prefer non-blocking fakes (`DirectExecutorService`, `FakeWorkManager`) over sleeps/waits; use Mockito only in :app tests, hand-written stubs in :component-network.

## Gotchas
- **WorkManager default initializer is removed** (manifest `tools:node="remove"` on InitializationProvider) — `MainApplication` provides the config manually. Don't re-add default init.
- `MainApplication` installs a crash handler that disposes the whole Provider before delegating — keep provider disposal idempotent.
- Read/favorite state syncs **by item link** across channels (`updateRssItemsIsReadByLink` etc.) — same article in multiple feeds shares state. Preserve this when touching item updates. `rss_item.link` is **indexed** since migration 11→12 (`index_rss_item_link`, Room's default `index_<table>_<column>` name — the migration must keep that exact name or Room's schema validation fails; exported schema in `base/schemas/…/12.json`). Older notes saying "link is unindexed, UPDATE = full table scan" are stale.
- Feed lists use keyset (cursor) pagination at page size 100 (`findRssItemsPageDesc/Asc`, `searchRssItemsPageDesc/Asc`; nullable cursor = first page) — no androidx.paging.
- **Link-grouped dedup queries** (issue #45): `findRssItemsPageGroupedByLinkDesc/Asc` + `findOlder/NewerRssItemGroupedByLink` collapse rows sharing a link into one representative. The GROUP BY expression is `COALESCE(NULLIF(link, ''), 'rss_item#' || id)` — NEVER plain `GROUP BY link` (all NULL links would collapse into one group and all empty strings into another; the sentinel gives invalid-link rows singleton groups). The representative (newest copy, tiebreak by highest id) is pinned by the query's single aggregate `MAX(printf('%015d_%015d', max(COALESCE(pub_date, created_date_time), 0), id))`: the 1-arg MAX is the aggregate that triggers SQLite's bare-column special case (result-set AND HAVING bare columns all come from the max row; needs SQLite ≥ 3.7.11, API 21 ships 3.8.4.3), the 2-arg `max(x, 0)` is the scalar clamp for pre-1970 dates, zero-padded 15-digit fields compare correctly under BINARY (the lexicographic order assumes each value fits in 15 digits: epoch millis hold until ~year 33000, autoincrement ids stay far below 1e15 — beyond that bound the string ordering breaks). The bare-column-from-max-row behavior has been VERIFIED to extend to the HAVING keyset predicate and ORDER BY on both SQLite 3.9.2 (API 24 emulator, exact Room SQL incl. the WHERE `:param IS NULL` filters and `index_rss_item_link`) and 3.45.3 — but it is only a documented guarantee for result-set bare columns, so re-verify on-device if the minSdk/SQLite range ever changes. Consequences: suppress `RoomWarnings.QUERY_MISMATCH` on these queries (the `rep_sort_key` column is intentional) and do NOT use `@RewriteQueriesToDropUnusedColumns` — a rewrite that drops the MAX aggregate silently kills the representative guarantee. `countRssItemsByLinks` chunks input links at 500 (`COUNT_BY_LINKS_CHUNK_SIZE`, mirrors `MARK_READ_BY_LINKS_CHUNK_SIZE`) because REFRESH-mode list windows can exceed 1000 rows and SQLite < 3.32 caps at 999 host parameters; it drops null/empty links so empty-link rows never count as copies of each other. The grouped queries are ALL-CHANNELS-ONLY (used when `PagedRssItemsCmd` has no selected channel AND the `collapseDuplicateStories` pref, default ON, is set); read/favorite filters apply at COPY level before grouping, and `RssItemDetailPage` switches to the grouped neighbor queries in the same context so next/prev walks exactly the collapsed list.
- `RssDateParser.parsePubDate/parseUpdated` return null on failure and log — callers must null-check.
- `RssFeedParser` throws on unrecognized root tag — new feed formats require explicit parser support + tests.
- List order + neighbor navigation + keyset cursor all use `(COALESCE(pub_date, created_date_time), id)` — `id` is the unique tiebreaker (created_date_time is not unique). Keep the three in sync if touching those DAO queries. Filter/sort/query/channel changes must do a FRESH load (cursor reset); mark-read/favorite/pull-to-refresh use REFRESH (window-preserving) — see `BaseRssItemsCmd`.
- Detail-page next/prev navigation requires a-navigator ≥ v0.0.73 (view-stack safe `replace()`); older versions desync the view stack and crash on back-press.
- Release signing depends on env vars (`SIGNING_KEY` etc.); local unsigned release builds are expected when unset.
- Changelog for release workflow is keyed by **versionCode** file name in `fastlane/metadata/android/en-US/changelogs/`.
- ILogger is a CompositeLogger (Android + File `cacheDir/alogger/app.log` + Toast) — don't use `Log`/`System.out` directly; use the provided `ILogger`.
- Volley cache dir is `cacheDir/volley` (20 MiB); ImageLoader LruCache holds 20 bitmaps — mind memory when adding image surfaces.
- Dynamic color is force-applied via theme overlay in `MainActivity` (M2 parent kept) — don't switch the app to a M3 theme parent without handling the M2 status-bar bridge.
- `.serena/memories/*.md` ARE tracked in git (only `.serena/cache/` and `.serena/project.local.yml` are gitignored) — commit memory updates together with the related change, as `chore(serena): ...` or bundled into a `docs:` commit.
- **Upsert retention (issue #37)**: `RssDao.upsertRssItemsForChannel` replaced the delete-all-and-reinsert `updateRssChannel` — existing-channel syncs match parsed items to stored rows by link (valid link) or by the null-safe `title + '\u0000' + pubDate-millis` tuple (null/empty link; the parser yields "" links for RSS items with an EMPTY `<link/>` element, null for items with NO `<link>` element, and null for Atom entries without an href — null and "" share one matching bucket), update matched rows in place (overwrite title/link/description/pubDate/media/categories, PRESERVE id/isRead/isFavorite/createdDateTime) and insert the rest. Items missing from the feed are RETAINED, never deleted (`deleteRssChannel` on feed removal remains the only history deletion); the returned list holds one row per DISTINCT item — intra-batch duplicates sharing a link/tuple-key collapse onto the single persisted row. Accepted edge: distinct linkless items that ALSO share a null/empty title and a null pubDate collapse onto one row (key `"\u0000-1"`) — bounded loss, stable across syncs. Consequences: (1) `rss_item.updated_date_time` for sync-touched rows doubles as "last seen in feed" — retained rows keep their old stamp; (2) the chained workers (RssSyncNotificationWorker, RssSyncChangeNotifierWorker) filter with `updated_date_time >= KEY_LONG_SYNC_START_MILLIS` (captured by RssSyncWorker, fallback 0 keeps old behavior for in-flight work) so retained unread items are not re-announced forever — note `updateRssItem` (manual edit) DOES stamp updated_date_time (one extra notification pass, accepted edge) while the by-link read/favorite updates do NOT stamp; (3) `RssRepository.unionMissingFavorites`/`applyItemState` are deleted — the DAO transaction is the single source of truth for the state merge, and `persist` returns updated+inserted rows (parsed order) followed by the retained rows.
- **Keep-read-items pruning (issue #37 phase 2)**: opt-in setting `keepReadItemsDays` (`AppSharedPreferences`, default 0 = off; settings row `KeepReadItemsMenuSV` right after the auto-mark-read entry; strings `menu_keep_read_items`, `keep_read_items_after_x_days`, `keep_read_items_off`, `keep_read_items_period_in_day`). When on, `RssSyncWorker.pruneOldItems` (in-worker, at sync end, right AFTER `autoMarkOldItemsRead`, catch-all never fails the sync) calls `RssRepository.pruneOldReadItems` → `RssDao.deleteOldReadRssItems`: `DELETE WHERE is_read = 1 AND is_favorite = 0 AND updated_date_time < cutoff`. The criterion is the Phase-1 last-seen stamp, NOT pub_date — pruning by pub_date would delete items still carried by their feed, which would come back UNREAD and re-notify (the pre-retention reinsertion trap); items still in a feed are re-stamped every sync and never pruned. Unread and favorites are NEVER deleted (compose: auto-mark-read ages unread→read, a later sync prunes); paused channels are included (global opt-in, same precedent as auto-mark-read). Deletion > 0 emits `RssChangeNotifier.itemsPrunedAuto(null)`; subscribers: `RssItemListSV` + `SearchRssItemListSV` reload their window. NO `refreshUnreadCount` wiring — deleting read rows cannot change unread counts.
